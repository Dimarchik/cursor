# Задание: доделать и запустить бота-снайпера мемкоинов на pump.fun (Solana)

Репозиторий: https://github.com/Dimarchik/cursor, ветка `claude/memecoin-trading-strategy-4wafc0`.
Работай в этой ветке. В `main` её ещё не вливали.

## Стратегия заказчика

1. Ловить создание каждой новой монеты на pump.fun и сразу покупать её на маленькую сумму.
2. Когда цена вырастет в 2 раза, продать часть, чтобы вернуть вложенное с учётом комиссий.
3. Остаток («moonbag») держать бессрочно в расчёте на 100x–1000x.
4. Видеть баланс и все позиции, желательно с телефона.

## Что уже сделано

- `RESEARCH.md` — ресерч. Выбрана Solana / pump.fun: около 30 000 запусков в день и лучший open-source инструментарий. Robinhood Chain и BNB рассмотрены и отложены.
- `bot/` — копия [chainstacklabs/pumpfun-bonkfun-bot](https://github.com/chainstacklabs/pumpfun-bonkfun-bot) (Apache 2.0, Python). Коммит оригинала записан в `bot/UPSTREAM_COMMIT`, список изменений — в `bot/NOTICE`. **Прочитай `bot/CLAUDE.md`**: там правила проекта и инварианты по продаже и RPC.
- В бот добавлена стратегия `exit_strategy: "recover_and_hold"`:
  - Основной код в `bot/src/trading/universal_trader.py`: методы `_handle_recover_and_hold_exit`, `_record_bag`, `_close_recovered`, `_stop_position_monitors`, плюс правки в `_attempt_position_exit` и `_run_exit_attempt`. Ещё `Position.recover_quantity` в `bot/src/trading/position.py`; валидация в `bot/src/config_loader.py`; параметры в `bot/src/bot_runner.py`.
  - Логика продажи: при цене ≥ `recover_multiplier` × цена входа продаётся `entry/price × (1 + recover_buffer)` позиции. На 2x с буфером 0.05 это 52.5%. Остаток записывается в `bot/trades/moonbags.jsonl` и убирается из `traded_mints`, чтобы cleanup не закрыл и не сжёг аккаунт.
  - Если за `max_hold_time` цель не достигнута, срабатывает `recover_timeout_action`: `sell_all` (продать всё, закрыть аккаунт, вернуть залог) или `hold`. Есть необязательный `stop_loss_percentage`.
  - В `yolo_mode` каждая позиция отслеживается отдельной asyncio-задачей, так что бот продолжает покупать. Лимит — `max_open_positions`. При остановке бота открытые позиции записываются в moonbags с причиной `shutdown`.
  - Готовый конфиг: `bot/bots/bot-recover-and-hold.yaml`, комментарии на русском. Остальные конфиги в `bot/bots/` выключены.
- `bot/tools/moonbags.py` — консольная утилита. Показывает баланс SOL и для каждого холда баланс токенов, цену и множитель. Цену берёт с bonding curve, а для монет, вышедших на биржу (graduated), — из DexScreener.
- `bot/tests/regression/verify_recover_and_hold.py` — офлайн-проверка новой стратегии. Команда `cd bot && uv run tests/regression/run_all.py` проходит 38/38.
- `README.md` в корне — инструкция для заказчика на русском.

## Задачи по порядку

### 1. Подготовка на сервере
- `git clone`, `git checkout claude/memecoin-trading-strategy-4wafc0`, затем `cd bot && uv sync && uv pip install -e .`, затем `uv run tests/regression/run_all.py`. Должно быть 38/38.
- RPC: подойдут бесплатные тарифы Helius, Chainstack или QuickNode, нужны и HTTPS, и WSS. Официальный `api.mainnet-beta.solana.com` сильно режет подписки, на нём бот не поймает новые монеты.
- Заказчик хочет **несколько RPC с автопереключением** при сбоях. Сейчас бот берёт один `SOLANA_NODE_RPC_ENDPOINT`/`SOLANA_NODE_WSS_ENDPOINT`. Добавь список запасных эндпоинтов с переключением при ошибках и таймаутах. Смотри `bot/src/core/client.py` (`SolanaClient`, `post_rpc`) и слушатели в `bot/src/monitoring/`.

### 2. Анализ за последние сутки: отработала бы стратегия или нет
- Возьми монеты pump.fun за последние 24 часа. Источники: Dune (таблицы pump.fun, нужен бесплатный API-ключ), Bitquery, API pump.fun (`frontend-api-v3.pump.fun`, свечи в `swap-api.pump.fun`) или выборка через RPC.
- Для каждой монеты смоделируй стратегию:
  - вход по цене через N секунд после создания, не раньше: первые блоки забирают снайперы и сам создатель; посчитай для N = 2, 5 и 10 с;
  - дошла ли цена до 2x в пределах `max_hold_time` (30 мин);
  - сколько стоит остаток сейчас.
- Учти комиссию pump.fun около 1–1.25% на каждую сделку, сетевые комиссии и залог за токен-аккаунт: 0.00203928 SOL на каждую монету в холде, возвращается только при полной продаже.
- Результат: доля монет, где вложенное вернули; P&L при `buy_amount` = 0.005 SOL; сколько SOL заморожено в залогах; стоимость холда сейчас. Если выборка, укажи её размер. Напиши выводы в `ANALYSIS.md` и пришли сводку заказчику.

### 3. Тестовый режим без денег (dry-run / paper trading)
- Добавь в бот флаг, например `trade.dry_run: true`, при котором он ловит реальные монеты, но вместо отправки транзакций записывает виртуальные покупки и продажи по реальной цене. Удобно перехватывать на уровне `PlatformAwareBuyer` / `PlatformAwareSeller` (`bot/src/trading/platform_aware.py`). Пример перехвата транзакций без отправки есть в `bot/tools/simulate_bot_buy_path.py`.
- Прогони dry-run несколько часов и сравни с результатом анализа из п. 2.

### 4. Telegram-бот для телефона
У бота нет никакого интерфейса, заказчик хочет управлять им из Telegram:
- уведомления о покупке, о возврате вложенного (с суммами), о продаже по таймауту или стоп-лоссу, об ошибках;
- команды `/balance`, `/bags` (холд, текущая стоимость, множитель), `/positions` (ждут цели), `/pause` и `/resume` (остановить и возобновить покупки, не трогая открытые позиции);
- отвечать только на `TELEGRAM_ALLOWED_USER_ID`; токен бота хранить в `.env` как `TELEGRAM_BOT_TOKEN`. Токен заказчик создаст у @BotFather.

### 5. Постоянная работа
Запусти бот как сервис (systemd или docker), с автоперезапуском и ротацией логов. Начни в режиме dry-run.

### 6. Реальные деньги — только с явного согласия заказчика
- Кошелёк — **отдельный новый**, только для бота. Рекомендация: 0.1–0.2 SOL на кошельке, `buy_amount: 0.005`. С $1 бот успеет открыть всего 3–4 позиции, остальное уйдёт в залоги за аккаунты.
- Перед запуском скажи заказчику, что именно запускается и сколько это может стоить, и дождись подтверждения.

- Никогда не выводи и не коммить содержимое `.env` и приватный ключ. Не коммить `logs/` и `trades/`.
- На GitHub полно поддельных «pump.fun sniper bot», которые крадут ключи. Не подключай сторонние репозитории и npm/pip-пакеты без проверки.
- Каждое изменение в `bot/src/` сопровождай офлайн-проверкой в `bot/tests/regression/` по образцу существующих; `run_all.py` должен оставаться зелёным.
- Линтер запускай только на изменённых файлах: `uv run ruff check --fix <files> && uv run ruff format <files>`. В проекте есть старый бэклог предупреждений, это нормально.
